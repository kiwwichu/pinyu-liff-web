## 正式切換的必要順序

1. 先完成資料表、權限與後台操作，不停止 Google Sheet。
2. 以只讀方式對照兩邊訂單、金額、折扣、訂金、尾款、抽成與提醒。
3. 建立 LINE 通知佇列、Google Calendar 同步、稽核與備份。
4. 選定切換日後短暫停止舊系統新增，做最後差異匯入。
5. 驗收後才把正式寫入切到 Supabase；舊試算表轉為唯讀封存。

## 不可直接照搬的舊邏輯

- 車馬費、服務單價、折扣與抽成必須保存「每張訂單當時的快照」，不能因日後調整家庭或保姆設定而回改歷史。
- 家庭編號是業務識別碼，不是驗證憑證。
- Sheet 的 onEdit、公式、顏色與鎖欄位不能當作權限；權限必須由 Worker 與資料庫共同執行。
- LINE、地址、電話、身分資料與簽名不可出現在公開 API、前端環境變數或 Git 紀錄。
