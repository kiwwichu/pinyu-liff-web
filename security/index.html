目前採取的保護

登入與角色權限

管理功能需要通過 LINE 身分驗證及後台角色檢查。一般訪客不能直接打開管理資料。

Supabase 資料庫預設拒絕

資料庫採用 Supabase PostgreSQL 與 RLS；業務資料不直接開放給匿名或一般登入角色，新資料物件也採先拒絕、再依需要明確授權。

敏感資料分開

地址、電話、完整合約與家訪內容分開保存，避免在家庭清單或一般畫面一次大量載入。

密鑰只放後端

具高權限的資料庫密鑰只存放於 Cloudflare Worker 的秘密設定，不放進公開 JavaScript、HTML 或下載檔案。

傳輸與瀏覽器防護

網站使用 HTTPS，並設定限制嵌入、內容類型判斷、來源資訊與瀏覽器功能的安全標頭。

最少顯示原則

客戶端只取得自身流程需要的資料；內部訂單備註與後端錯誤細節不直接回傳給一般使用者。

Supabase 平台安全與隱私依據

第三方合規與稽核

Supabase 官方表示其平台符合 SOC 2 Type 2，並取得 ISO 27001 資訊安全管理認證；相關控制涵蓋其託管的資料庫、Storage、Auth 與 API 等服務。

資料傳輸與保存

Supabase 官方說明，客戶資料在靜態保存時使用 AES-256 加密，傳輸過程使用 TLS，並持續進行內部安全檢查與滲透測試。

客戶資料的處理角色

Supabase 隱私政策說明：對應用程式客戶資料，Supabase 主要依客戶指示以資料處理者身分提供服務；正式權利義務仍以雙方適用的政策與合約為準。

安全是共同責任

Supabase 負責其雲端基礎設施與平台控制；Pinyu 仍需負責帳號、RLS、API 密鑰、角色授權、應用程式與實際資料使用方式。

重要：使用通過認證的供應商，不代表 Pinyu 整個系統自動取得 SOC 2 或 ISO 27001 認證，也不代表零風險。我們會同時維護自己的權限、程式與作業流程。

SOC 2 與責任範圍 Supabase 隱私政策 共同責任模型

誰可以看到什麼

客戶

因營運、服務與緊急處置需要管理完整資料；敏感內容仍應避免無目的瀏覽或轉傳。

我們不做不實保證

安全措施可以降低風險，但不能把風險降到零。帳號遭竊、裝置遺失、第三方服務事件、程式缺陷、人為設定錯誤或尚未被發現的新型攻擊，都可能造成影響。我們會持續檢查、修補與縮小資料存取範圍，不以「百分之百安全」作為宣稱。

發現問題時

若你看到不屬於自己的資料、可疑登入、錯誤收件人或其他隱私問題，請立即透過快樂小狗 Pinyu LINE 官方帳號通知。初次回報請先描述畫面與時間，不要在公開留言貼出電話、地址、身分證或完整截圖。

我們會先限制可能的存取、保存必要紀錄、確認影響範圍，再依實際情況修正與通知受影響對象。
